# Infrastructure Inventory

Operational inventory of every managed provider and delivery platform supporting **Health Vitals**.

## Provider Matrix

| Concern | Provider | Purpose | Dependent Apps | Environments | Data Processed / Stored | Repo Configuration | Impact if Unavailable | Official Docs | Maintainer |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Database** | **Neon (PostgreSQL)** | Primary relational database for users, sessions, tokens, files, clinical reports, observations, and LLM telemetry. | `apps/api`, `apps/worker`, `apps/jobs/migrator` | Production (local uses Postgres 17 in `compose.yml`; CI uses Postgres 18 service) | PII (`users.email`), Argon2 password hashes, hashed session/reset tokens, clinical biomarker measurements, `llm_requests` metrics. | [`neon.ts`](../../neon.ts), [`database/migrations/`](../../database/migrations/), [`infra/production.env.example`](../../infra/production.env.example) | **Critical outage:** Auth, uploads, extraction persistence, and dashboards fail (`/health` returns `503`). | [Neon Docs](https://neon.tech/docs) | Repo owner |

| **Email Delivery** | **Resend** | Sends branded transactional HTML/text emails (`noreply@binderlex.com`) for email verification and password recovery. | `apps/api` (via `packages/platform/src/mail/resend.ts` & `packages/emails`) | Production (local/tests use `MockMailProvider` or Nodemailer) | Recipient email addresses and single-use verification/recovery URLs. | [`packages/platform/src/mail/resend.ts`](../../packages/platform/src/mail/resend.ts), [`packages/emails/`](../../packages/emails/), [`infra/dns/README.md`](../../infra/dns/README.md) | **Degraded auth flows:** New registrations fail verification dispatch and password recovery emails cannot be sent; existing logged-in users unaffected. | [Resend Docs](https://resend.com/docs) | Repo owner |

| **DNS & Domain** | **Cloudflare** | Authoritative DNS for `binderlex.com` routing web traffic to Vercel, API traffic to Fly.io, and email auth (SPF/DKIM/DMARC) for Resend. | `apps/web`, `apps/api`, Resend | Production | DNS records only (no application data). | [`infra/dns/README.md`](../../infra/dns/README.md) | **Domain unreachable:** Users cannot resolve `binderlex.com` or `api.binderlex.com`; outbound email deliverability degrades if TXT records are lost. | [Cloudflare DNS Docs](https://developers.cloudflare.com/dns/) | Repo owner |
| **CI/CD & Source Control** | **GitHub / GitHub Actions** | Git hosting plus automated CI checks (`lint`, `infra:check`, `typecheck`, `migration:run`, `test`, Docker image builds on `main`). | All workspaces (non-runtime) | CI / Development | Source code and test fixtures only (no production secrets or patient data). | [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml), [`.github/ISSUE_TEMPLATE/`](../../.github/ISSUE_TEMPLATE/), [`.github/pull_request_template.md`](../../.github/pull_request_template.md) | **No runtime impact:** Live production services continue running; merges and automated CI checks pause until GitHub recovers. | [GitHub Actions Docs](https://docs.github.com/en/actions) | Repo owner |

## Automated Parity Verification

Run `bun run infra:check` (executed automatically in GitHub Actions) to verify that `neon.ts`, `apps/web/vercel.json`, `infra/fly/*.toml`, `infra/production.env.example`, `infra/dns/README.md`, and `packages/platform/src/config/env.ts` remain synchronized.
